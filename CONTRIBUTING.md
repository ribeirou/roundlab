# Contribuindo

1. Leia a especificação e o plano em `docs/`.
2. Crie uma branch com nome curto, por exemplo `feat/importacao`.
3. Mantenha o trabalho dentro do MVP aprovado.
4. Verifique o comportamento alterado e descreva a validação no pull request.
5. Abra pull request para `main`.

Não envie credenciais, arquivos `.env`, dados brutos de partidas ou informações pessoais irrelevantes. Dados derivados só devem ser publicados após revisão de conteúdo e das condições de uso.

## Frentes de trabalho

- Importação, normalização e relatório de qualidade.
- Métricas com evidências e testes dos casos ambíguos.
- Interface de equipe e detalhe do round.
- Pauta de treino e exportação.

As interfaces entre essas partes estão no plano. Combine alterações nesses contratos com a equipe antes de desenvolver partes dependentes.

Ainda não existem comandos para executar a aplicação ou testes. Quem implementar a primeira etapa deverá documentar os comandos reais no README.
